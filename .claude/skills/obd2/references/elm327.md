# ELM327 / clone AT commands and the deck's init

The Vgate iCar Pro speaks the ELM327 command set over a serial stream; the deck reaches that
stream through a BLE GATT service (notify = replies, write = commands). Each command ends in one
`\r`; the reply ends with `\r\r>` (the `>` prompt means "ready"). Commands are case-insensitive
on the chip, but the deck's gate only accepts its exact upper-case strings.

## The deck's init (verified with the old clone, 2026-10-19; `setup()` in `src/obd/obdlink.cpp`)

| Command | Reply | Why |
|---|---|---|
| `ATZ` | `ELM327 v1.5` (old clone) / `ELM327 v2.x` (Vgate, to log) | reset; clones take seconds before the next command answers → 4 s wait, one retry |
| `ATE0` | `OK` | echo off (otherwise the command comes back before the data) |
| `ATL0` | `OK` | no line feeds, `\r` only |
| `ATS0` | `OK` | no spaces: `410C1AF8` (the parser tolerates spaces anyway) |
| `ATH0` | `OK` | headers off (the parser's anchors assume it; tolerates 7Ex headers) |
| `ATSP0` | `OK` | protocol auto: the first OBD request prints `SEARCHING...` for up to ~5 s |

Then `0100`/`0120`/`0140`/`0160` (the supported scan, first one with a 5 s wait), then the poll.
Each setup command waits 3 s with one retry; a timed-out reply sets `s_late` and the next ask
drains until `>` first (the clone answered >1 s late and every value drifted one behind).

## Commands worth knowing (all read-only on the car)

| Command | Effect | In deck gate? |
|---|---|---|
| `ATI` | chip id string (`ELM327 v1.5` / `v2.1` / `v2.2`...) | yes |
| `AT@1` | device description (Vgate prints its own string) | no |
| `ATDPN` | protocol number now (`A6` = auto found 6) | yes |
| `ATDP` | protocol name | no |
| `ATRV` | the adapter's reading of pin 16 (battery), e.g. `12.6V`; clones can be far off → compare with PID 42 | yes |
| `ATSP6` | force ISO 15765-4 CAN 11/500 (skips the search) | no (candidate: faster connect) |
| `ATAT0/1/2` | adaptive timing off / normal (default) / aggressive | no (candidate: AT2 speeds polling) |
| `ATST hh` | reply timeout = hh × 4 ms (default `32` hex ≈ 200 ms; adaptive timing shortens it) | no |
| `ATSH xxx` / `ATCP hh` | request header: 11-bit `7DF` / `7E0`; 29-bit `ATCP 18` + `ATSH DA10F1` (the City's engine) | **no** — needs a gate test |
| `ATCRA xxx` | only accept replies from this ID | no |
| `ATCAF0/1` | CAN auto-format (PCI bytes hidden when 1, default) | no |
| `ATCFC0/1` | automatic flow control (default 1: multi-frame works) | no |
| `ATMA` | monitor all bus traffic — **floods BLE, not for the deck**; car-can-lab's sniffer only | **never** in deck |
| `ATPP`, `ATBRD`, `ATWS`, `ATD` | change stored parameters / baud / reset to defaults | **never** |
| `ATLP` | adapter low-power mode | no |

## Reply words

`OK`, `?` (command not understood), `SEARCHING...`, `NO DATA` (no ECU answered: PID unsupported,
or ignition off), `UNABLE TO CONNECT` (no protocol found: ignition off / engine ECU asleep),
`CAN ERROR`, `BUS INIT: ...ERROR`, `BUFFER FULL` (the BLE side can't drain fast enough),
`STOPPED` (a char arrived while it was waiting: the deck never sends during a reply), `<DATA
ERROR`, `7F xx yy` (negative response: service xx, reason yy, e.g. `7F 22 31` request out of
range). `obd::parse` maps them to NoData / NoEngine / Error.

## Multi-PID and reply-count tricks (from the datasheet)

- **Reply count suffix:** `010C1` = "one reply expected": the ELM returns as soon as one ECU
  answers instead of waiting its timeout. On a 3-ECU car this is the biggest single speed-up, but
  it only works when the engine ECU answers first, and the deck's gate refuses 5-char requests
  today (a change with a test).
- **Multi-PID:** on CAN, mode 01 accepts up to 6 PIDs in one request (`010C0D11`), answered in one
  (often multi-frame) reply per ECU. Fewer round trips, harder parsing. Not used yet.
